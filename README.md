# StickerCountApp

シールが貼ってあるアンケートパネルの写真を選択すると、シールを自動で数えて記録するアプリ

## 作った動機
カンファレンスでブース出展をした際に、ブースにシール貼り付け式のアンケートパネルを置くことが度々ある。パネルに貼られたシール数＝ブースに来訪した人の数として報告するため、毎回協賛終わりには300枚ほどのシールを5分程度かけて手作業で数えていて手間がかかっていた。そのためアプリを使ってその手間を簡略化したくてこのアプリを作った

## できること(使い方)
1. 履歴画面右上の＋ボタンをタップ
2. アンケートパネルの写真をアルバムから選択
3. 選択した写真上の黄色枠のサイズを以下に注意して調整し、トリミング  
※回答枠＝各選択肢の貼る範囲として囲っている枠
    - 回答枠まで含めること
    - 回答枠の線と黄色い枠が重ならないようにすること
    - シール以外のものが入らないようにすること
4. 枚数を確認し、カンファレンス名を入力して「保存」
    - 再計測したい場合は「再トリミング」
    - 計測結果を保存しない場合は「トップに戻る」
5. 履歴画面に戻り、日付、カンファレンス名、計測枚数が記録される

## 技術構成
* Swift＝アプリのメイン言語
* SwiftUI＝メインUI
* SwiftData＝計測した枚数とカンファレンス名、日付を記録するために使用
* Vision＝シールの輪郭検出に使用
* CGContext＝ピクセルの取り出しと、白黒マスクの作成
* UIImagePickerController＝ライブラリから写真を取り出すために使用
* UIViewControllerRepresentable＝UIKit の画面を SwiftUI に置く
* Coordinator＝選択した写真を受け取る
* Xcode 26.3、iOS 26.0(Deployment Target)、シミュレーター(iPhone 16e)＝アプリの動作確認に使用

## 学んだこと(開発の流れ)
* 白いパネルと明るさが近い淡色シールが輪郭検出から漏れていると考え、シールを白、背景を黒とする彩度マスクを実施。 当初の不足データはトリミングの座標計算にバグがあり、意図と違う場所を切り抜いていた影響と判明。仮説の根拠となるデータが確実に正しいものであるかを確認することの大切さを学んだ。修正後に再検証、淡色シールの未検出を改めて確認した
* enumを使って状態遷移を管理することで、case crop(UIImage)のように各画面に必要なデータを一緒に管理できるようにした。これにより定義をenumに集約できるので、保守性が上がったと思われる

## 精度の検証と改善
* Visionを使ってシールの輪郭を検出することでシールの枚数を数えることを試したが、二つ課題があった。画像によってシールのサイズがまちまちで画像に対する割合が一貫しないため、サイズの問題は、トリミングの指示書きを修正し、一定の改善が行えた(指示を直す前は約−16%、直した後は約−4〜−9%)。もう一つはシールの色が多岐に渡り背景の白と判別がつかないことだが、これについては後述するピクセル操作で改善した
* ピクセルごとにRGBの最大値と最小値の差が60以上だった場合はシールとして白に変換し、背景は黒とすることで、シールとしての判定を容易にした。Visionと比較して、慎重にトリミングした場合、おおよそ検出精度は-26%から+2.7%まで改善した（上述した−4〜−9%は指示書きどおりに調整した場合）。それでも画像に対するシールの割合が一貫しないため、結果の正確性に難が残っていると考える

## 既知の制限
1. 手持ちの iPhone(iOS 26.6.2)に対応する Xcode は、macOS 26.2 以上が必要だが、 macOS 15.7.4 で、入れられる最新の Xcode は 26.3だった。Xcode 26.3 ではこの iPhone にビルドできなかったため、実機での動作確認ができていない(シミュレーターのみ)。実機で動作させた場合想定外の動きをする可能性がある
2. 検証したのは、同じ企業のパネル2枚のみ。レイアウトが大きく異なるパネルは未検証のため、検出結果が大きくぶれる可能性がある
3. 検証した写真は、正面から撮ったもののみであり、斜めや遠くから撮った写真では検証していないため、精度は不明。シールの枚数を正確に数えることが最終目的のアプリのため、正面から撮影した写真を前提とする
4.  トリミング範囲で、推定枚数が変わる(枠の取り方で約−17%〜+15%、指示書きどおりでも約−4〜−9%)ため、個人の裁量によって推定枚数に影響が出る
5. 閾値(彩度60、面積 0.0005〜0.005)は、2枚の写真に合わせて調整している。部屋の照明で白パネルの彩度が変わる（2枚の写真では4〜16と26〜55）ため、別の照明では閾値の調整が必要になる可能性がある

## 今後の改善
* （制限1への対応）Xcodeのバージョンが手持ちのスマホのバージョンに対応したら実機で動作確認を行う
* （制限2への対応）他社のパネルや回答枠がないタイプのパネルの写真などの様々な写真で検証し、対応させる
* （制限4への対応）枠が正確なサイズに設定できていなくても、±5%程度の精度が出せるように過不足分を手動タップで補正する方法を検討する
* （制限5への対応）様々な写真のデータをもとに、最適な閾値を検証していく
* （制限1への追加対応）実機検証が可能になった際に、カメラ直接撮影に対応させていく
